# АВТОПИЛОТ НЕПРЕРЫВНОГО УЛУЧШЕНИЯ VeloC (AUTOPILOT.md)

Данный документ определяет регламент автономного функционирования, протоколы реагирования и скрипты непрерывного цикла разработки языка и экосистемы VeloC.

---

## 1. Входные Сигналы и Триггеры

Автопилот непрерывного цикла реагирует на 4 типа сигналов:

| Тип сигнала | Источник | Реакция / Приоритет |
|---|---|---|
| **TEST_FAILURE** | Падение `veloc ci`, `veloc test`, conformance suite | **P0 (Критический)**: Немедленная остановка, локализация регрессии бисекцией, исправление. |
| **BENCH_REGRESSION** | Деградация метрик в `veloc bench` более чем на 3% | **P0 (Критический)**: Проверка флагов Clang, генерации SIMD ассемблера, устранение регрессии. |
| **BUG_REPORT** | Невалидный код, ошибка парсера/sema, ICE компилятора | **P1 (Высокий)**: Создание минимального воспроизводимого теста (MRE), фикс в парсере/sema, верификация. |
| **FEATURE_REQUEST** | Недостающие возможности стандартной библиотеки, tooling, ergonomics | **P2 (Плановый)**: Оценка целесообразности, согласование с философией zero-cost, реализация. |

## 2. Непрерывный Цикл Автономной Разработки

Каждая итерация автономной работы следует строгому детерминированному циклу:

```
               ┌───────────────────────────────┐
               │    1. ВЫБОР ЗАДАЧИ ПО P0-P2   │
               └──────────────┬────────────────┘
                              ▼
               ┌───────────────────────────────┐
               │     2. РЕАЛИЗАЦИЯ В D:\VeloC   │
               └──────────────┬────────────────┘
                              ▼
               ┌───────────────────────────────┐
               │  3. ПОЗИТИВНЫЕ + НЕГАТИВНЫЕ   │
               │            ТЕСТЫ              │
               └──────────────┬────────────────┘
                              ▼
               ┌───────────────────────────────┐
               │     4. ЧЕСТНЫЙ ЗАМЕР СКОРОСТИ │
               │      (БЕЗ ВЫДУМЫВАНИЯ)        │
               └──────────────┬────────────────┘
                              ▼
               ┌───────────────────────────────┐
               │   5. ФИКСАЦИЯ В PROGRESS.md,  │
               │    CHANGELOG.md, DECISIONS.md │
               └──────────────┬────────────────┘
                              ▼
               ┌───────────────────────────────┐
               │     6. АТОМАРНЫЙ GIT COMMIT   │
               └───────────────────────────────┘
```

1. **Выбор задачи**: Сверяется с `QUEUE.md` и открытыми `todo` в `PROGRESS.md`. Выбирается наивысший доступный приоритет.
2. **Реализация**: Строго внутри `D:\VeloC`. Все допущения фиксируются в `DECISIONS.md`.
3. **Тестирование**: Добавление positive и negative тестов. Запуск `python veloc.py ci` (все 23+ теста обязаны быть зелёными).
4. **Бенчмарк**: Сравнение с C++ / старой версией с реальным измерением на физическом оборудовании.
5. **Документирование**: Обновление чек-листа в `PROGRESS.md`, добавление записи в `CHANGELOG.md` (с миграционным гайдом при breaking changes).
6. **Git Commit**: Атомарный коммит с префиксом Conventional Commits (`feat:`, `fix:`, `perf:`, `docs:`).

## 3. Лимиты и Стоп-Факторы (Когда Требуется Человек)

Автопилот работает полностью автономно, **за исключением следующих стоп-факторов**, при которых он обязан остановиться и запросить решение человека:

1. **Семантическая неоднозначность ядра языка**:
   - Изменение базового порядка вычислений, противоречащее `docs/spec/04_eval_order.md`.
   - Добавление новой концепции владения или синтаксиса, конфликтующего с существующими конструкциями.
2. **Невоспроизводимый аппаратный краш**:
   - Сбой ядра/ОС, зависание внешнего линкера `ld.lld`, аппаратные ошибки памяти.
3. **Необъяснимое падение производительности**:
   - Деградация более 10%, не устранимая стандартными оптимизациями векторизации Clang.
4. **Внешние сетевые публикации**:
   - Публикация пакетов во внешние репозитории, пуш в удаленный GitHub, регистрация доменов. Все артефакты подготавливаются локально, публикация — только после явного `yes` человека.

## 4. Скрипт Автопилота (`veloc autopilot`)

Инструмент `python veloc.py autopilot` выполняет полный прогон цикла:
- Проверка чистоты репозитория и статуса тестов.
- Автоматический запуск регрессионных бенчмарков с порогом деградации $\le 3\%$.
- Генерация отчета о здоровье экосистемы.
