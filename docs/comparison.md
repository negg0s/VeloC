# Честное сравнение: VeloC vs C++, Rust, Zig, Odin, Jai, Go

В этом документе приведено строгое техническое сравнение языков по ключевым характеристикам, включая **слабые стороны VeloC** и сценарии, когда VeloC выбирать **НЕ стоит**.

---

## 1. Сравнительная матрица

| Критерий | VeloC | C++ (Clang/MSVC) | Rust | Zig | Go |
|---|---|---|---|---|---|
| **Скорость сборки (Debug)** | **Мгновенная (<250ms)** | Медленная (заголовки) | Медленная (LLVM + borrow) | Быстрая | Очень быстрая |
| **Пиковая скорость кода** | **Экстремальная (AVX2/FMA)** | Экстремальная | Высокая | Высокая | Средняя (GC overhead) |
| **Управление памятью** | **Явное (Arena / Pool)** | Ручное (RAII / new) | Borrow Checker | Ручное (Allocator) | Сборщик мусора (GC) |
| **Встроенный SoA/SIMD** | **Нативный (`soa struct`)** | Нет (ручные макросы) | Нет (библиотеки) | Базовый | Нет |
| **Зрелость экосистемы** | Молодая (v9.2) | 40+ лет | 10+ лет (crates.io) | Активная бета | Зрелая |
| **Отладка и Tooling** | Clang PDB / VS Code | Мощный | Отличный | Развивающийся | Отличный |

---

## 2. Сильные стороны VeloC
1. **Сверхбыстрая компиляция**: Кэширование CAS и инкрементальные запросы собирают код за доли секунды.
2. **Встроенный SoA (Structure-of-Arrays)**: Язык автоматически генерирует выровненные по 32 байта массивы для векторизации без ручной возни с интринсиками.
3. **Бесшовный C++ интероп**: Прямая кодогенерация в чистый C++ устраняет накладные расходы на FFI.
4. **Контролируемая память**: Первоклассные аллокаторы (`Arena`, `TrackingAllocator`, `StaticPool`) гарантируют отсутствие неожиданных фрагментаций и пауз.

---

## 3. Слабые стороны VeloC (Когда НЕ стоит выбирать VeloC)
1. **Когда нужен формально доказанный Borrow Checker**: Если ваша команда требует гарантий времени компиляции на уровне многопоточных ссылок без единого runtime-проверки - выбирайте **Rust**.
2. **Когда критична максимальная экосистема готовых библиотек**: Если проекту нужны тысячи редких сторонних SDK (AWS, Stripe, специфичные драйверы) прямо сейчас из реестра - выбирайте **C++** или **Go**.
3. **Когда разрабатываются веб-бэкенды общего назначения**: Для типичных CRUD API с высокой текучкой разработчиков простота и развитая стандартная библиотека **Go** превосходят ручной контроль над памятью.
4. **Кроссплатформенная поддержка**: Текущая реализация ориентирована на x86_64 с AVX2 под Windows/Clang 20; мобильные платформы (iOS, Android ARM) находятся в стадии разработки.
